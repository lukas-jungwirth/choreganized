Lists: a slimmer overview, and three ways to add

This pass follows your five questions. Empty lists are gone, Recently bought has moved into the card it belongs to, the row of chips is out, and a list can be opened by itself to work in it.

Every phone works: open a list, tick a row, type in the field, press Start over.

Your five questions

Each one weighed. Where I disagree, it says so.

  • Should lists without items be shown?No. You are right.An empty list only needs a place to be added to, and the list menu in the field gives it one. A list stays on screen while it still has something bought today, so a wrong tick can be undone, then it goes.
  • Is Recently bought relevant, or an unnecessary divider?Relevant, but not as a section.It is the only way back from a wrong tick once Undo has gone, and mid-shop it answers "did you get the milk already?". As a heading between lists it was a divider. Now it is one quiet line inside the card: "2 bought".
  • Is "Add to" intuitive? Can I focus on one list?The chips were the weak part. Focus is the better idea.You would not have scrolled per item (the choice stuck), but five chips in a row that scrolls sideways hides the fifth. Three replacements are below to try. I would build the first two together.
  • Does the new list sheet need the explanations?No. Cut."Shopping list" and "Checklist" say it. To make a wrong pick harmless, the kind can be switched later. The cost: a one-off list like "Party" has to call itself a shopping list.
  • Should a checklist get a due date? Or both kinds?Shopping lists no. Checklists maybe, later.A packing list has a new date on every trip, so the date belongs to this run, not to the list, and it should not grow into a second Tasks tab. Drawn further down so you can judge it.

Adding: three ways to try

Each phone does one thing differently. Add a few items to Vacation packing in each and see which one your thumb agrees with.

What I would build

A and B together

A covers the quick case from the overview: milk, or the one thing for the hardware store. B covers the long case: packing, or walking one shop. Together they also let empty lists disappear, because the menu still reaches them.

  • 1Tap the header to fold, the corner button to openA shopping list shows its rows on the overview and folds like any section. The button with the two arrows opens a list full screen. A checklist is a single row and opens wherever you tap it.
  • 2Where an item landsOpened list: that list. Overview: the list on the icon, which is the first shopping list unless the name is known or you picked another.
  • 3Amounts in the same line"2 l milk" becomes Milk · 2 L. The sliders button is gone; tapping a row still opens the sheet to edit.
  • 4What does not changeDrag to reorder, the tick that plays out in place, the undo bar, live ticks from the other phone, recipes pouring in.

A date on a checklist?

Drawn so you can judge it. I would leave it out of the first build and add it after one real trip, if you missed it.

  • +What it would doShow "in 8 days" on the list, bring the list to the top of the overview in its last three days, and send one push the evening before if anything is unticked.
  • +It belongs to this runOptional, one date for the whole list, cleared by Start over. "Before we leave" would never have one.
  • −Not on shopping listsYou shop when you shop. The one real deadline, shops closing for a holiday, is already announced.
  • −The riskDates per row, reminders and owners are what the Tasks tab is. If a list needs those, it is a task. One date per list is where this would have to stop.
